# T16 — Internationalisation (English + German)

**Mode:** agent+check · **Priority:** P2 · **Depends on:** T08 · **Estimate:** 3h — **do before T09; cut only after T11 and T12** · **Your time:** 20 min (German wording review)

## Goal
The UI, server error messages and the "nothing found" refusal appear in the visitor's language (English or German); adding a third language means adding one message file, not touching components.

## Your part
- Decide the refusal approach below before the agent starts (it changes the e2e assertions).
- Approve the new dependency (`next-intl`) — `AGENTS.md` forbids adding one unasked.
- Read the German strings once; the agent translates, you judge tone and terms.

## Context
- `docs/scope.md` §5 lists "Multi-language UI / i18n" as out of scope. This task reverses that: update the row (move it to a "done in T16" note) and add a decision to `docs/decisions.md` as `proposed`.
- Chat answers already follow the question's language (prompt rule, `lib/chat/prompts.ts`, `chat-v2`); this task does not touch the prompt.
- `conventions/code.md` governs UI code; user-facing server messages live in `lib/errors.ts` (`principles.md`, DRY table) and must stay the single home for them.
- Dates already use `Intl.DateTimeFormat(undefined, …)` (`components/notebook-card.tsx`); pass the active locale instead of `undefined`.

## Scope
- **Library:** `next-intl` (App Router, server components and server actions). Read its docs against this repo's Next.js version in `node_modules/next/dist/docs/` first — see the warning in `AGENTS.md`.
- **Locale selection, no URL routing:** a `locale` cookie, falling back to `Accept-Language`, falling back to `en`. A language switch in the footer sets the cookie. No `/de/...` paths (KISS; the demo gate and e2e URLs stay as they are).
- **Message files:** `messages/en.json` and `messages/de.json`, same keys, grouped by feature. A test fails when the key sets differ.
- **Extract every user-facing string** from components, server actions and `lib/errors.ts` into the messages; no hardcoded English left in toasts, banners, empty states, labels or aria-labels.
- **`<html lang>`** reflects the active locale.
- **Refusal when nothing relevant is retrieved** (`NO_CONTEXT_ANSWER`, `app/api/chat/route.ts`): currently a fixed English string that skips the model. Pick one:
  - (a) a tiny model call with no context that states it in the question's language — costs quota and latency, needs the usage limits already checked;
  - (b) static en/de strings chosen by the *UI* locale, not by guessing the question's language.
    Default if undecided: (b), since it is free, deterministic and keeps the e2e assertions stable.
- **Docs:** README (languages supported, how to add one), `docs/architecture.md` (directory layout, locale flow), `docs/scope.md`, `docs/decisions.md` (proposed).

## Out of scope
- Translating chat answers, guides or audio (they follow the question or the sources' language already).
- Translating uploaded documents or source titles.
- Right-to-left languages, locale-prefixed URLs, per-user stored language preference.
- Languages beyond English and German.

## Acceptance criteria
- [ ] With the cookie unset and `Accept-Language: de`, the notebooks page, workspace, dialogs and error messages are German; with `en` or an unsupported language they are English
- [ ] The footer switch changes the language without a page reload loop and the choice survives a reload
- [ ] `de.json` and `en.json` have identical key sets (unit test)
- [ ] No hardcoded user-facing English remains in `app/`, `components/` or `lib/errors.ts` (review by grep, listed in the report)
- [ ] The refusal appears in the language chosen under *Scope* for a German question and an English question
- [ ] Existing e2e specs pass unchanged under the default English locale; one new spec switches to German and asserts a heading and an error message
- [ ] The German strings were read by the human (human)

## E2E tests (Playwright, `e2e/`)
- Open the app with a German `Accept-Language`, see German headings; switch to English via the footer, reload, still English
- Trigger a mapped error (e.g. invalid input) in German and see the German message

## Notes for the agent
- Keep `lib/errors.ts` the single source of messages: map error codes to message *keys*, translate at the boundary that knows the locale.
- Do not translate log lines or anything in `usage_events`; logs stay English and content-free (`security.md` §12).
- Plural and date/number formatting go through ICU messages / `Intl`, never hand-rolled (`code-style`: standards over hand-rolling).
- Server actions are public endpoints: the locale cookie only picks a language; it must never influence authorization or which rows are touched.
